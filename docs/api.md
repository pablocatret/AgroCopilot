# API reference

The FastAPI application is defined in `backend/api.py`. The default local base URL is:

```text
http://localhost:8000
```

Interactive OpenAPI documentation is available from FastAPI at `/docs` while the service is running.

## Conventions

- Request and response bodies use JSON unless stated otherwise.
- Attachment upload uses `multipart/form-data`.
- Identifiers are opaque strings; clients must not derive meaning from their format.
- Timestamps generated by the stores are UTC.
- The API currently has no authentication or authorisation layer.
- Most case endpoints accept or default to `workspace_id=local`.

```json
{
  "status": "ok",
  "version": "0.1.0"
```


## Chat

### `POST /chat`

Runs one orchestration request.

Request:

```json
{
  "query": "The northern field is showing signs of water stress. What should I inspect?",
  "conversation_id": "optional-existing-conversation",
  "user_id": "local",
  "language": "en",
  "decision_mode": "case",
  "response_mode": "conversation",
  "memory_enabled": false,
  "continuity_mode": "auto",
  "attachment_ids": [],
  "case_id": null
}
```

Fields:

| Field | Required | Default | Notes |
| --- | --- | --- | --- |
| `query` | yes | — | Natural-language request |
| `conversation_id` | no | generated | Reuses a stored conversation when valid |
| `user_id` | no | none | Also acts as the workspace identity in the current client |
| `language` | no | `es` | Requested answer language |
| `decision_mode` | no | `case` | Typed by `DecisionMode` |
| `response_mode` | no | `conversation` | Currently only `conversation` is supported |
| `memory_enabled` | no | `false` | Enables opt-in user memory |
| `continuity_mode` | no | `auto` | `auto`, `off` or `explicit` |
| `attachment_ids` | no | empty | Identifiers returned by `/attachments` |
| `case_id` | no | none | Explicit case to use when applicable |

The response contains:

```json
{
  "plan": {
    "steps": ["case_manager", "writer"],
    "missions": [],
    "runs": {},
    "dependencies": {
      "writer": ["case_manager"]
    },
    "allow_replan": false,
    "response_mode": "conversation",
    "policy": {},
    "diagnostics": {}
  },
  "answer": {
    "executive_summary": "...",
    "message_md": "...",
    "response_path": "multi_agent_synthesis",
    "references": [],
    "limitations": [],
    "next_actions": []
  },
  "conversation_id": "...",
  "clarification": null
}
```

The exact response is governed by `AgentPlan`, `FinalAnswer` and `ClarificationRequest` in `libs/schemas.py`.

If a requested attachment identifier does not exist, the API returns HTTP 400:

```json
{
  "detail": {
    "error": "missing_attachments",
    "message": "Faltan adjuntos solicitados para ejecutar el caso.",
    "attachment_ids": ["unknown-id"]
  }
}
```

The error text is currently Spanish even when the requested answer language is English.

## Progress events

### `GET /events/{conversation_id}`

Opens a `text/event-stream` response. Each SSE `data` field contains a JSON-encoded runtime event.

Typical event categories include:

- execution and agent status;
- log messages;
- replan metadata;
- errors; and
- a final status event with `stage=completed`.

Clients must treat new event fields and types as forwards-compatible additions. The broker retains at most 100 recent events per in-memory conversation and may replay disk-backed events when `SSE_LOG_MODE=disk`.

The endpoint does not create a chat execution. Subscribe using the same `conversation_id` supplied to or returned by `/chat`.

## Attachments

### `POST /attachments`

Uploads one or more files as multipart field `files`.

```bash
curl -X POST http://localhost:8000/attachments \
  -F "files=@field-notes.pdf" \
  -F "files=@measurements.csv"
```

Response:

```json
{
  "attachments": [
    {
      "attachment_id": "...",
      "filename": "field-notes.pdf",
      "content_type": "application/pdf",
      "size_bytes": 12345
    }
  ]
}
```

Limits:

- no more than six files per request;
- no more than 10 MiB per file; and
- only configured document, spreadsheet, text and image extensions.

Use the returned identifiers in `POST /chat`.

## Cases

### `GET /cases`

Query parameters:

- `workspace_id` — default `local`
- `status` — optional case status
- `limit` — default `50`

Valid status values are `active`, `on_hold`, `closed`, `archived` and `deleted`.

### `POST /cases`

```json
{
  "workspace_id": "local",
  "title": "OL-17 water-stress review",
  "objective": "Determine the next field inspection"
}
```

### `GET /cases/{case_id}`

Accepts optional query parameter `workspace_id`.

### `PATCH /cases/{case_id}`

Updates title or objective:

```json
{
  "workspace_id": "local",
  "title": "Updated title",
  "objective": "Updated objective"
}
```

### `POST /cases/{case_id}/status`

```json
{
  "workspace_id": "local",
  "status": "on_hold"
}
```

### `GET /cases/{case_id}/events`

Returns stored case events. Query parameters are `workspace_id` and `limit`.

## Assertions

Assertions hold case or workspace facts with provenance and lifecycle status.

### `GET /cases/{case_id}/assertions`

Query parameters:

- `workspace_id`
- optional `status`

### `POST /cases/{case_id}/assertions`

```json
{
  "workspace_id": "local",
  "key": "crop",
  "value": "olive",
  "provenance": "user_statement",
  "status": "confirmed",
  "assertion_type": "fact",
  "display_text": "The parcel is planted with olives",
  "confidence": 1.0
}
```

The endpoint always creates a case-scoped assertion.

### `GET /assertions`

Lists global assertions for a workspace.

### `POST /assertions`

Creates a global assertion. The request must contain `"scope": "global"`.

### `POST /assertions/{assertion_id}/status`

Valid statuses are `proposed`, `confirmed`, `superseded`, `retracted` and `expired`.

```json
{
  "workspace_id": "local",
  "status": "superseded"
}
```

### `POST /assertions/{assertion_id}/correct`

Creates the corrected assertion state:

```json
{
  "workspace_id": "local",
  "value": "almond",
  "display_text": "The parcel is planted with almonds"
}
```

## Tasks and observations

### `POST /cases/{case_id}/tasks`

```json
{
  "workspace_id": "local",
  "title": "Measure pressure at the northern branch",
  "rationale": "Check the irrigation hypothesis",
  "priority": "high",
  "status": "open"
}
```

Priorities are `high`, `medium` and `low`. Task statuses are `proposed`, `open`, `blocked`, `done` and `cancelled`.

### `POST /case-tasks/{task_id}/status`

```json
{
  "workspace_id": "local",
  "status": "done"
}
```

### `POST /cases/{case_id}/observations`

Returns HTTP 201 on success.

```json
{
  "workspace_id": "local",
  "date": "2026-07-24",
  "parcel": "OL-17 North",
  "campaign": "2026",
  "note": "Two rows show reduced canopy density",
  "severity": "media"
}
```

The current severity enum uses the Spanish values `baja`, `media` and `alta`.

## Opt-in memory

Memory endpoints are retained for explicit user context and compatibility. They are separate from authoritative explicit cases.

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/memory/{user_id}` | Read the current editable memory |
| `PUT` | `/memory/{user_id}` | Replace permitted editable sections |
| `DELETE` | `/memory/{user_id}` | Delete all memory for a user |
| `GET` | `/memory/{user_id}/list` | List named memories |
| `POST` | `/memory/{user_id}/create` | Create a named memory |
| `PUT` | `/memory/{user_id}/current` | Select the current memory |
| `PUT` | `/memory/{user_id}/{memory_id}/rename` | Rename a memory |
| `DELETE` | `/memory/{user_id}/{memory_id}` | Delete one memory |

The editable sections accepted by the update endpoint are `profile`, `preferences`, `farm_context` and `open_questions`.

## Costs

### `GET /costs/summary?days=7`

Returns the aggregate cost estimate for the requested number of days.

### `GET /costs/conversation/{conversation_id}`

Returns the estimate for one conversation.

### `GET /costs/pricing`

Returns the configured pricing catalogue.

Cost responses are estimates derived from local usage records and catalogue values. They are not provider invoices.

## Error model

FastAPI validation errors, including enum values rejected by the request models,
use HTTP 422. Application errors commonly use:

- HTTP 400 when a request passes shape validation but violates a business rule,
  or when attachment identifiers are missing;
- HTTP 404 for a missing case, assertion, task, memory or conversation; and
- HTTP 201 for a successfully created observation.

Error messages are not yet represented by a single versioned error schema. Clients should rely on HTTP status and stable structured fields where available rather than parsing human-readable text.

## Example end-to-end call

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Summarise what should be inspected before deciding on treatment.",
    "user_id": "local",
    "language": "en",
    "decision_mode": "case",
    "response_mode": "conversation",
    "continuity_mode": "off",
    "memory_enabled": false,
    "attachment_ids": []
  }'
```

For a deterministic local run, start the service with `DISABLE_EXTERNALS=1`. The resulting answer will reflect offline limitations.
